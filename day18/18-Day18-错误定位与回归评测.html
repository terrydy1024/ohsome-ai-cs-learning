错误定位与回归评测

区分意图、权限、API、检索、生成、护栏和人工接管问题，建立版本回归机制。

本章目录本章任务1. 定位顺序2. 最小证据包3. 常见误判4. 回归矩阵5. 版本判断练习与验收面试追问

看到错误答案后，真正专业的动作不是马上修改Prompt，而是用完整trace判断问题发生在哪一层、由谁负责、要跑哪些回归。

贯穿事故
AI把马来西亚积分规则回答给新加坡用户。团队第一反应是更换模型，但trace显示模型忠实引用了检索结果，根因是知识元数据错误和市场过滤失效。换模型不会解决串库。
本章完成后，你需要做到：
  • 把失败归因到稳定错误层和错误码
  • 收集能复现问题的最小证据包
  • 根据变更类型选择正确回归范围
  • 比较候选与基线并识别关键回退
01

错误定位顺序

P0命中？ ├─ 是 → 阻断发布/流量 + 保全trace └─ 否 → 预期动作是否正确？ ├─ 否 → 意图 / 槽位 / 会话 / 路由 └─ 是 → 身份与对象归属是否正确？ ├─ 否 → 身份 / Tool Gateway └─ 是 → 工具与API是否正确？ ├─ 否 → 工具 / 参数 / API / 数据 └─ 是 → 知识与检索是否正确？ ├─ 否 → 知识 / 元数据 / 切片 / 召回 / 排序 └─ 是 → 生成 / 护栏 / 人工接管
02

不能缺少的证据

层关键证据能判断什么
会话原文、intent、slots、selected object、state意图与上下文污染
权限auth、scope、ownership、字段白名单越权和跨账号
工具/API工具、参数摘要、状态码、业务结果、Schema版本选择、参数、服务与数据问题
RAGquery、filters、TopK、doc/chunk/version知识、串库、召回和排序
生成Prompt/模型版本、回答、输出校验忠实度、遗漏和护栏
03

四个常见误判

API错却改Prompt

源数据错误时，模型只是忠实表达错误事实。

检索错却换模型

错误国家规则进入上下文，再强的模型也可能回答错。

护栏拦截当模型拒答

先确认是上游置信度、输出规则还是模型本身。

人工SOP错归咎AI

AI交接正确，但人工给错口径，应修人工流程。

04

变更决定回归范围

变更必跑原因
模型或System Prompt回答、工具、拒答、多语言、P0集可能影响全链路行为
工具Schema/API工具选择、参数、错误码、相关端到端需要检查契约和失败恢复
知识/切片/检索RAG全集、版本串库P0、证据正确性避免正确率提升但串库
工作流/原因树相关异常全集、原因码、工单和人工接管路径变化会引入遗漏
权限/网关全部安全红队集P0高风险变更
05

候选版本如何判断

示例结论：不发布。候选版本普通质量、资产、工具和转人工均提升，但新增1个P0错误，且P95完整响应从4.8秒升到5.3秒。平均分提升不能覆盖安全和性能回退。

版本报告必须列出所有回退样本，而不是只展示平均指标。每个失败样本需要错误码、Owner、修复方案和回归范围。

练习与验收

问题1

AI引用了错误国家规则，应该先查哪些证据？

问题2

修改会员API返回字段后，为什么不能只测API接口？

问题3

候选版本平均分提升，但新增一个P0，应该怎样处理？

参考答案
检查市场上下文、query filters、文档元数据、生效版本、TopK和最终引用；API字段会继续影响Tool Gateway、参数/结果解析、原因树、回答和人工交接，需要跑接口契约及相关端到端；立即阻止发布，保全trace、修复并运行P0与相关回归集。
答

面试追问

回答错误时你怎么排查？
先看P0和预期动作，再按身份、工具、API、知识、检索、生成、护栏和人工接管顺序检查trace，先上游后下游。
每次都跑全量回归吗？
按变更影响选择子集以控制成本，但P0集每次必跑；模型、元数据过滤、权限等广泛或高风险变更建议全量。
如何验证修复不是只针对一个句子？
用稳定错误码找到同类样本，运行该错误模式的回归子集，再运行相关端到端和P0集。
