# OH!SOME 多国家会员 AI 客服：意图识别与路由规范 V1

## 1. 结论

采用“业务域 + 服务动作 + 场景 ID + 槽位 + 风险标记”的结构化输出，不让模型直接决定接口或人工流程。模型结果是候选，系统规则才拥有执行权。

## 2. 输出结构

```json
{
  "domain": "points",
  "action": "DIAGNOSE",
  "scene_id": "PTS-05",
  "slots": {"order_id": "系统选择的本人订单"},
  "confidence": 0.91,
  "top2_intents": ["points.missing.diagnose", "points.earn_rule.explain"],
  "risk_flags": []
}
```

## 3. 六类服务动作

- QUERY_ASSET：读取本人实时资产。
- EXPLAIN_RULE：检索当前国家、渠道和版本的规则。
- QUERY_AND_EXPLAIN：资产事实与规则证据组合回答。
- DIAGNOSE：进入确定性异常工作流，可能调用多个只读工具。
- NAVIGATE：引导到页面或门店，不执行关键业务变更。
- HANDOFF：转人工并携带已确认上下文。

## 4. 置信度与降级

普通问答初始门槛为 Top1 ≥ 0.80 且 Top1-Top2 ≥ 0.12；异常和个人资产建议提高到 0.85/0.15。以上均为模拟项目初值，必须通过真实标注集校准。风险词、投诉、隐私和越权不依赖单一置信度，采用规则与模型任一命中即升级。

## 5. 槽位原则

1. 优先由登录态、入口、本人订单/券列表自动填充。
2. 一次只追问一个会改变路由的高价值槽位。
3. 账号、订单、券等对象优先让用户从本人列表选择，不要求手工输入完整ID。
4. 完整生日、卡号、验证码等不进入普通模型上下文。
5. 槽位有生命周期；跨话题或身份切换必须清理。

## 6. 关键边界

- “积分规则”与“我的积分没到”不能混为一个意图。
- “券过期”与“要求补偿”要分开；后者不能自动承诺。
- 投诉、隐私和明确人工请求优先于普通业务意图。
- 多意图允许拆分执行，但每个子任务都要独立校验权限。
