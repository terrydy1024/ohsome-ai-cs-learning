# OH!SOME 多国家会员 AI 客服｜第一阶段项目方案 V1

> 版本：Day 7 学习实战版  
> 范围：整合 Day 1—Day 6  
> 事实边界：CRM/会员中台/App/H5/会员规则为真实经验底座；AI客服建设过程、经营基线、排期和效果均为模拟学习内容，不能表述为未经证实的真实上线事实。

## 1. 项目判断

OH!SOME 多国家会员服务的问题不是“没有聊天机器人”，而是四类服务能力没有统一：

1. **会员资产查询**：积分、等级、券和权益必须基于当前会员的真实数据；
2. **会员规则解释**：不同国家、品牌、业务线和生效版本的规则必须正确隔离；
3. **异常问题诊断**：积分未到账、券不可用、生日礼未发需要跨订单、流水和规则做多步判断；
4. **高风险人工处理**：投诉、赔偿、账号合并和隐私请求不能由AI自动决定或执行。

因此首期产品不是一个“知识库聊天框”，而是一套由会话入口、意图理解、受控编排、会员工具、RAG、回答护栏和人工客服共同组成的服务系统。

## 2. 项目目标

### 2.1 用户目标
- 会员能够在非人工服务时段查询本人资产并获得规则解释；
- 遇到常见异常时，能够得到基于真实订单和规则的原因说明；
- 需要人工时，不必重新描述全部问题。

### 2.2 业务目标
- 降低高频重复咨询的人工作业量；
- 提升多国家会员规则的一致性；
- 减少积分、券和权益问题对使用与复购的阻断；
- 建立可评测、可追踪、可持续改进的AI服务能力。

### 2.3 安全目标
- 会员资产事实只能来自本人授权API；
- 国家和版本规则必须硬过滤；
- P0错误（跨账号、资产编造、错误承诺补偿等）为0；
- 不可逆和资产写入操作不进入首期Agent工具箱。

## 3. 首期范围

### 3.1 纳入
- 积分余额、流水、有效期和未到账诊断；
- 等级、成长值和升级规则；
- 优惠券列表、规则和不可用原因；
- 生日礼、折扣权益和权益状态；
- 基础账号/登录问题引导；
- 公开门店与会员规则；
- 工单创建和人工接管。

### 3.2 不纳入
- AI自动补积分、补券、退款或赔偿；
- 账号合并、注销和隐私删除自动执行；
- 复杂投诉完全自动处理；
- 语音客服、主动外呼和营销推荐；
- 多Agent自治网络。

## 4. 总体架构

```text
App/H5/官网/客服渠道
        ↓
会话接入与身份上下文
        ↓
意图候选 + 槽位 + 风险识别
        ↓
代码路由 / 状态机 / 权限校验
   ┌────────┬─────────┬─────────┐
   ↓        ↓         ↓         ↓
本人API    RAG规则   异常工作流  人工接管
   └────────┴─────────┴─────────┘
        ↓
事实合并 + 答案生成 + 输出护栏
        ↓
回答 / 追问 / 导航 / 转人工
        ↓
日志、评测、运营与知识回灌
```

架构原则：
- 模型负责语言歧义，代码负责流程和校验；
- 下游业务系统负责事实、权限和资格；
- 所有高风险动作必须在模型之外审批；
- 每一步都要有结果码、失败路径和审计信息。

## 5. 意图与会话设计

意图不做成50个互斥大标签，而是输出：

```json
{
  "domain": "points",
  "service_action": "diagnose_exception",
  "scene_id": "PTS-05",
  "slots": {"order_ref": null, "purchase_time": "2026-07-20"},
  "risk_flags": [],
  "confidence": 0.81
}
```

当槽位不足、Top1与Top2接近、存在多意图或高风险覆盖时，系统进入追问、拆分或人工路径。多轮对话使用状态机保存任务、对象和已确认事实；身份、国家、订单或优惠券对象变化时必须清理旧上下文。

## 6. 身份与安全设计

- 登录态只确认当前主体，不确认任意订单、券或权益属于本人；
- 工具调用使用认证系统注入的会员token，模型不接触原始凭证；
- 下游系统再次校验工具scope和对象归属；
- 原始API响应经过字段最小化适配后才进入模型；
- 服务身份只拥有场景白名单中的只读能力；
- 审计记录工具、参数摘要、结果码、版本和转人工原因，不记录验证码、token或完整敏感数据。

## 7. 模拟项目推进（不是历史事实）

1. **第1阶段：场景与方案**——客服数据盘点、50个场景、MVP范围、总体架构；
2. **第2阶段：数据与知识**——只读会员API、规则知识库、国家/版本治理；
3. **第3阶段：灰度与评测**——Golden Set、人工抽检、P0门槛、少量流量；
4. **第4阶段：运营优化**——失败回灌、知识更新、工具与工作流优化。

## 8. 第一阶段验收

进入Day 8之前，应能够：
- 5分钟讲清为什么做、做什么和不做什么；
- 画出系统链路并说明每层责任；
- 给出积分余额、积分规则、积分未到账和投诉四种不同路由；
- 解释意图、槽位、会话状态和身份权限如何协同；
- 明确AI项目的模拟边界，不把学习产物冒充真实生产结果。

## 9. 面试讲述结构

1. 业务背景和问题；
2. 为什么不能只做RAG问答；
3. 场景拆解与MVP取舍；
4. 总体架构和模型/代码/业务系统边界；
5. 意图、会话和身份安全；
6. 后续API、RAG、评测和灰度计划；
7. 关键风险和复盘。
