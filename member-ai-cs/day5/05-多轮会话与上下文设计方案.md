# OH!SOME 多国家会员 AI 客服：多轮会话与上下文设计方案 V1

## 1. 核心结论

多轮会话不等于无限保留聊天历史。产品采用状态机管理任务进度，并将上下文分层保存：系统事实、已确认对象、模型候选、工具事实、知识证据、去敏聊天文本。每层都有明确来源、生命周期和清理触发。

## 2. 追问原则

1. 先由入口、登录态、账号、本人订单/券列表自动补齐。
2. 一次只追问一个会改变路由或结果的高价值信息。
3. 普通异常最多追问两次，高风险或明确人工请求最多一次。
4. 订单、券和权益优先使用本人选择器，不让用户手工输入长ID。
5. 达到追问上限仍不能处理时，说明缺失信息并转人工或提供自助入口，禁止循环追问。

## 3. 上下文清理

- 换账号：清理全部个人对象、工具事实和旧答案。
- 换国家：保留来源国家，新增目标国家，重新检索目标规则。
- 换订单/券：清理旧对象及其状态，不得沿用旧原因。
- 登录失效：清理个人上下文，公共规则仍可解释。
- 人工接管：锁定AI关键业务执行，只展示排队状态。
- 会话结束或超时：清理任务级对象，只留最小审计记录。

## 4. 失败恢复

工具超时只允许受控重试一次；RAG无有效证据时不得从其他国家或旧版本补答案；恢复失败进入人工或服务不可用降级。任何失败都不能让模型根据历史消息猜测会员资产。
