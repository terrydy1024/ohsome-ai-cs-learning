Agent 与受控工作流

理解Agent、Tool Calling、代码编排和多Agent的区别，为会员服务选择“足够智能但不过度自治”的架构。

本章目录本章任务1. Agent是什么2. 编排方式3. 推荐架构4. 五种模式5. 调用控制6. 失败恢复练习与验收面试追问

Agent的价值不是让模型拥有更多权力，而是在明确边界内完成多步任务。对于会员客服，越接近资产、权限和赔偿，越需要确定性系统接管。

贯穿事故
用户说“这张券不能用，直接给我退款”。一个全自治Agent先查券，再自行选择退款工具并执行。即使最终用户满意，这个系统仍然是失败的：模型越过了资格、金额、审批和审计边界。

01

Agent到底是什么

产品层面可以把Agent理解为：配置了指令、工具和运行循环的模型执行单元。运行时，模型可能输出最终答案，也可能请求调用工具、读取结果并继续处理。

Agent ≠ 聊天框

聊天框只是入口；Agent包含决策、工具、循环和状态。

Agent ≠ 多Agent

单个Agent加工具已经能完成很多任务。

Agent ≠ 自由执行

可以由代码限制工具、顺序、轮次和审批。

Agent ≠ 业务规则引擎

确定性资格和权限应由业务系统执行。

五种场景编排模式

固定单工具

积分余额：身份→工具→模板。

固定RAG

公开规则：硬过滤→检索→引用。

API+RAG混合

本人过期积分+有效期规则。

受控状态机

积分未到账、券不可用等原因树。

人工优先

投诉、赔偿、隐私和账号合并。

05

一次工具调用必须经过哪些控制

  1. 场景白名单：当前场景只能看到必要工具。
  2. 严格Schema：类型、枚举、长度、必填和禁止额外字段。
  3. 系统参数注入：会员token、国家和trace不由模型生成。
  4. 完整授权：下游系统再次校验scope和对象归属。
  5. 结果适配：裁剪原始响应，返回稳定业务事实。
  6. 有限重试：只对可重试错误重试一次。
  7. 最大轮次：避免循环、成本失控和重复写入。
  8. 输出护栏：工具结果并不自动等于可展示答案。

安全参考：https://genai.owasp.org/llmrisk/llm062025-excessive-agency/

06

三类典型失败

选错工具

代码白名单拒绝，回到澄清，而不是尝试相邻工具。

工具循环

相同参数去重，达到最大轮次后停止或转人工。

部分成功

API成功但RAG失败，只回答已确认事实，不补全规则。

重要：工具结果、RAG文档和用户输入都属于不可信数据。它们可以提供事实或证据，但不能改变工具权限和系统指令。

答

面试追问

你们是单Agent还是多Agent？
首期采用单入口服务Agent配合代码工作流，不做多Agent网络。会员服务的核心难点是权限、事实和规则治理，不是专家Agent数量。后续如果业务域、团队和工具规模显著扩大，再评估专家Agent或Handoff。
Agent自主度如何控制？
按场景定义工具白名单、严格Schema、系统参数注入、最大轮次、超时、有限重试和人工审批。模型可以提出候选动作，但代码与业务系统拥有最终执行权。
最终答案对了，工具选错了算通过吗？
不算。错误工具可能泄露数据、增加成本或在未来版本产生严重后果。Agent评测必须同时检查轨迹、参数、顺序、结果使用和安全。
