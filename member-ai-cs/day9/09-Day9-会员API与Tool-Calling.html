会员 API 与 Tool Calling

把积分、优惠券、等级、订单和工单能力设计成严格、只读、最小权限、可失败恢复的AI工具。

本章目录本章任务1. API与工具区别2. 工具目录3. 输入Schema4. 返回协议5. 错误码6. 未到账轨迹练习与验收面试追问

Tool Calling的产品工作不是列出“需要调用积分接口”，而是把每个业务能力设计成模型能正确选择、系统能安全执行、失败后能恢复的窄工具。

贯穿事故
开发直接把内部CRM通用查询接口暴露给模型，参数包括任意member_id和字段列表。模型虽然只想查积分，却能请求手机号、订单和风控字段。这不是Prompt问题，而是工具功能和权限过宽。
本章完成后，你需要做到：
  • 设计工具名称、描述、输入Schema和返回协议
  • 区分模型参数、系统注入参数和业务系统校验
  • 定义错误码、重试、幂等和部分成功
  • 完成50个场景到工具轨迹的映射
01

内部API和AI工具有什么区别

内部API面向AI的工具
可能服务多个后台和复杂参数一个工具只完成一个清晰任务
返回大量内部字段返回最小业务事实协议
调用方自行处理权限系统注入身份并在下游完整授权
错误码偏技术稳定区分无记录、无权限、冲突、超时
可能含写入能力MVP只保留必要的受控写入
02

工具目录如何拆

资产查询

积分、等级、券、权益、订单和活动均为本人只读。

资格判断

券可用性、订单计分资格由确定性服务返回原因码。

知识与导航

知识检索带市场/语言/版本过滤；导航只生成白名单深链。

受控写入

仅工单创建和人工接管，必须幂等。

03

输入Schema的核心不是格式，而是权限边界

{
  "name": "coupon_eligibility.check",
  "input": {
    "type": "object",
    "properties": {
      "coupon_ref": {"type": "string", "maxLength": 64},
      "order_ref": {"type": ["string", "null"], "maxLength": 64},
      "channel": {"type": "string", "enum": ["app","h5","pos","ecommerce","theme_park"]}
    },
    "required": ["coupon_ref", "channel"],
    "additionalProperties": false
  },
  "system_injected": ["member_token","market","trace_id"]
}
关键设计：Schema里没有任意member_id。会员主体来自认证上下文，模型无法通过参数切换到另一个会员。
04

统一返回协议

{
  "success": true,
  "trace_id": "tr_xxx",
  "tool_version": "1.2",
  "queried_at": "2026-07-31T10:00:00+08:00",
  "data": {"eligible": false, "reason_code": "CHANNEL_NOT_SUPPORTED"},
  "evidence_refs": ["rule_sg_coupon_2026_v3"],
  "redaction_applied": true,
  "error_code": null,
  "retryable": false
}

模型只根据最小事实和证据生成答案。`trace_id`和`tool_version`用于定位和回归，不作为用户回答内容。

05

错误码必须区分业务含义

错误码含义产品处理
NOT_FOUND本人范围内没有记录说明未找到，允许重新选择
NOT_OWNED对象不属于本人不暴露存在性，记录安全事件
TIMEOUT技术超时有限重试；不得生成事实
NO_EVIDENCE没有有效规则证据拒答或人工
DATA_CONFLICT多个事实源冲突停止结论，创建异常工单
DUPLICATE重复受控写入返回已有工单/接管记录
06

以“消费积分未到账”为例

选择订单order_summary.read
判断资格order_points_eligibility.check
查流水points_ledger.search
查规则knowledge_search.search
原因判断代码原因树
异常接管case_create / handoff

模型可以抽取用户说的时间和订单线索，也可以把原因码解释成自然语言，但不能自己判断订单是否计分，也不能在冲突时自动补积分。

练

练习与验收

问题1

请为“查询本人积分余额”写出工具的输入、系统注入参数、返回字段和主要错误码。

问题2

为什么`NOT_FOUND`和`TIMEOUT`不能使用同一句“暂时查不到”？

问题3

工单创建为什么必须使用幂等键？幂等键应由谁生成？

参考答案
余额工具只接受必要业务条件，会员token和市场由系统注入；返回余额、冻结、近期过期和查询时间。无记录表示事实不存在，超时表示事实未确认，产品动作不同。幂等防止模型重试或网络重放造成重复工单，应由可信服务端生成并绑定会话、动作和业务对象。
答

面试追问

Tool Calling和调用普通API有什么区别？
底层仍会调用API，但产品层要增加工具描述、严格Schema、模型可见参数、系统注入参数、完整授权、返回协议、错误恢复、最大轮次和审计。工具是AI运行时的安全业务能力，不是原始接口别名。
为什么不让模型传member_id？
会员主体是权限上下文，不是业务参数。由模型或用户提供member_id会形成跨账号风险；服务端应使用当前认证主体，并对订单、券和权益做对象归属校验。
接口超时后模型能否先解释通用规则？
可以把已确认的通用规则和未确认的个人事实分开回答，但必须明确“当前余额/状态无法查询”，不能用规则推断个人资产。若用户问题核心依赖个人事实，应重试或转人工。
