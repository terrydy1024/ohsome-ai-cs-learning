# Day 8｜Agent 与受控工作流设计说明

## 1. Agent是什么

在产品层面，Agent可以理解为：**配置了指令、工具和运行循环的大模型执行单元**。模型可以在一轮或多轮中决定是否调用工具、读取工具结果并继续处理。Agent并不自动等于“多Agent”，也不意味着所有步骤都必须交给模型自主规划。

官方参考：
- https://openai.github.io/openai-agents-python/agents/
- https://openai.github.io/openai-agents-python/tools/
- https://openai.github.io/openai-agents-python/multi_agent/

## 2. OH!SOME为什么不采用全自治Agent

会员客服同时具备规则确定、个人资产敏感、国家差异大和写操作风险高等特征。完全由模型决定工具、顺序和业务动作，会引入错误工具、错误参数、循环调用、跨账号、规则串用和错误承诺等风险。

因此采用混合架构：

```text
模型：理解语言、抽取槽位、提出候选、组织表达
代码：状态机、路由、Schema、超时、重试、最大轮次、风险拦截
业务系统：身份、对象归属、资产事实、资格判断、权限与写操作
人工：投诉、赔偿、隐私、账号合并、复杂冲突和兜底
```

## 3. 五种编排模式

1. **固定单工具流程**：积分余额等本人只读查询；
2. **固定RAG流程**：纯规则解释；
3. **代码编排的API+RAG混合流程**：个人过期积分+过期规则；
4. **受控状态机/原因树**：积分未到账、券不可用等多步异常；
5. **人工优先/受控交接**：隐私、账号合并、赔偿投诉。

只有第四类具有有限的Agent式多步决策，但工具集合、前置条件、最大轮次和失败处理仍由代码控制。

## 4. 一次安全工具调用的生命周期

```text
用户问题
→ 模型输出候选意图/槽位
→ 代码确认场景与允许工具
→ 身份和对象校验
→ JSON Schema参数校验
→ 调用工具
→ 结果协议校验与字段最小化
→ 模型根据事实/证据生成回答
→ 输出护栏与审计
```

任何一步失败，都不能由模型“补全”事实。

## 5. 关键控制

- 每个场景只暴露必要工具；
- 安全参数由服务端注入；
- 下游系统执行完整授权；
- 工具参数采用严格Schema；
- 只对可重试错误重试一次；
- 相同参数调用去重；
- 按模式限制2—5个模型轮次；
- 工单创建使用幂等键；
- 工具文本、知识文档和用户输入都属于不可信数据，不能改变权限；
- 资产写入和隐私操作需要专用审批。

安全参考：
- https://genai.owasp.org/llmrisk/llm062025-excessive-agency/
- https://genai.owasp.org/llmrisk/llm01-prompt-injection/

## 6. Agent评测指标

- 意图/任务理解正确率；
- 工具选择正确率；
- 参数完整与正确率；
- 工具顺序正确率；
- 任务完成率；
- 有限重试成功率；
- 不必要工具调用率；
- 平均/最大模型轮次；
- 安全违规与越权调用数；
- 转人工正确率。

最终答案正确但工具轨迹越权，仍应判定失败。
