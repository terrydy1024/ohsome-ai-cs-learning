# BO账户与乐园会员真实业务补充说明

> 本说明根据用户在 2026-08-05 提供的真实业务补充整理。涉及BO账户与One ID的学习内容，以本说明为准；它用于校正原始技术方案中未完整描述的账户接入与乐园集成关系。

## 1. BO集团会员入口

BO集团会员始终只有一套注册与会员主体，并不存在零售会员、电商会员两套独立集团账号。

### 电商路径

1. 用户在电商页面触发注册或登录；
2. 页面跳转到BO集团会员注册入口；
3. 用户完成注册或登录；
4. 成功后再跳回电商；
5. 电商继续使用同一个BO集团会员身份。

### 线下零售路径

1. 线下门店提供二维码；
2. 用户扫码进入H5，也可以下载App；
3. 用户完成BO集团会员注册或登录；
4. 注册成功后，首页展示或弹出会员二维码；
5. 结账时用户出示会员码，门店扫描后累计积分。

因此，“电商入口、门店二维码、H5、App”只是不同访问路径，最终都进入同一套BO集团会员体系。

## 2. 乐园会员体系

乐园原本就有一套独立会员/账号体系，属于外购系统。即使不接BO集团会员，乐园也可以独立运行。

乐园账号必须保留，因为乐园资产和业务能力依赖乐园系统自己的账号主键。

## 3. BO与乐园的接入方式

### 路径A：用户先注册BO集团会员

1. 用户通过BO H5或App注册集团会员；
2. 用户到乐园后扫描关联二维码；
3. 系统查询是否已有乐园账号；
4. 没有时，在乐园外购系统创建乐园账号；
5. 创建成功后，将BO会员账号与乐园账号建立关联。

### 路径B：用户先注册乐园账号

1. 用户在乐园完成手机号注册；
2. 乐园将注册结果同步给BO；
3. BO查询或创建集团会员；
4. 系统自动将两边账号绑定关联。

## 4. 历史用户处理

乐园历史账号最初只使用手机号。BO集团会员则支持手机号、邮箱、Apple ID和Google认证等注册/登录方式。

历史用户处理采用手机号作为两边共同的匹配字段：

1. 标准化手机号和国家码；
2. 查找对应BO会员与乐园账号；
3. 一对一命中时建立账号关联；
4. 一对多、缺失或异常数据进入人工处理；
5. 两边原账号与资产保持不变。

## 5. 账号关联与资产边界

项目没有把乐园资产迁移到BO系统。

- BO积分、等级和BO权益继续由BO会员系统管理；
- 乐园资产继续由乐园系统管理；
- BO与乐园保存账号映射关系；
- 需要展示乐园资产时，通过接口查询或跳转乐园页面；
- 用户两边都有账号时，处理的是“合并关联关系”，不是删除某一账号或搬迁乐园资产。

## 一句话架构

```text
电商 / 门店H5 / App
        ↓
BO集团会员（单一会员主体）
        ↕ 双向开户与账号关联
乐园外购会员账号（独立业务账号）

BO资产留在BO；乐园资产留在乐园系统。
```
