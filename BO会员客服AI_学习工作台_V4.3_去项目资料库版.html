技术理解卡：只学到PM够用

RAG

让模型临时查正式知识。你要决定何时用、知识怎么管、怎么验收。

知识片段（Chunk）

长资料拆成可检索业务单元。你管语义边界，不写token参数。

知识标签（Metadata）

国家、语言、版本、生效时间等过滤条件。

语义检索（Embedding）

按意思相似找资料。理解作用即可，不学数学。

混合检索 / 重排

提高“找对知识”的能力。PM用Case验收，不负责算法实现。

业务工具（Tool Calling）

AI需要本人事实时调用业务能力。你管权限、业务语义和失败。

上下文（Context）

这一轮模型实际看到的证据和规则。你管证据优先级。

安全护栏（Guardrail）

限制隐私、支付、写资产等风险，不能只靠Prompt。

执行轨迹（Trace）

一次请求每一步发生了什么。PM用它定位错误层。

更底层的向量算法、缓存、并发、模型部署、接口代码不属于本课程学习目标。

0. 项目一句话

在印度尼西亚会员H5/App会员中心提供印尼语/英语AI自助客服，优先解决规则问答、当前登录会员本人数据查询、规则+数据解释，并在异常或人工动作场景下创建异步客服工单。

红线：不修改Stars/Coins/等级，不自动退款/改订单，不合并账号，不查其他会员数据，不查询付费会员支付流水，不伪造支付结果。

1. 场景与MVP

用户问题事实一期AI做到哪里失败去向
Coins多久过期？当前规则解释规则无有效知识则明确无法确认
我的Coins还有多少？本人实时数据登录后只读查询数据失败则重试/人工
为什么这笔订单没Coins？订单+Coins流水+规则组合证据解释事实冲突/原因不明建单
帮我补100 Coins需核查事实不执行写入；整理问题用户确认后人工工单
查朋友手机号余额他人数据安全拒绝说明只能查询本人

2. 用户服务主流程

用户提问→理解问题→身份/权限检查→规则/数据/组合处理→回答→已解决？→必要时工单

登录成功后恢复原问题；多订单时让用户选择；数据失败不猜；工单必须用户二次确认。

4. 当前会员核心规则（课程当前口径）

  • 印度尼西亚：每笔订单每10,000 IDR = 1 Star + 1 Coin，按单向下取整，不跨订单合并。
  • Stars：不按单笔过期；等级按滚动365天Stars判断。
  • Coins：每笔到账后365天过期，优先使用最早到期批次。
  • 等级：Lv2≥200、Lv3≥600、Lv4≥1,200、Lv5≥2,000 Stars；可跨级升级。
  • 退款会减少Stars，但不因此立即降级；降级按等级周期检查，当前项目口径每次最多降一级。
  • 成长会员与付费会员是独立对象。

5. 知识库方案

  1. 先建立知识源台账，确定每条规则的业务Owner和正式真源。
  2. 把稳定业务主题整理为Knowledge，并使用Version管理变更；当前有效版本不可被静默覆盖。
  3. 检索前按国家、语言、状态、生效时间做硬过滤。
  4. 再做关键词+语义召回、排序；用检索评测Case验“是否找对”，而不是让PM指定底层参数。
  5. 回答只使用当前有效知识；没有证据就明确无法确认。

6. 数据能力清单

能力允许关键边界
本人Coins/Stars/等级是必须绑定当前登录身份；只读
本人订单/权益（一期定义范围）是空值、失败、超时语义要区分
其他会员数据否不能通过手机号等自由替换查询对象
付费会员支付流水否不能因此判断支付成功/失败
修改资产/订单/退款否人工处理

7. 回答与安全规范

  • 规则事实来自当前知识；个人事实来自本人业务数据；两者冲突时不自行裁决。
  • 禁止把用户陈述当系统事实，例如“我已经扣款”≠“支付成功”。
  • 禁止跨会员、写资产、伪造支付/退款结果。
  • 能力不足时说清“我能确认什么 / 不能确认什么 / 下一步是什么”。
  • 工单由用户确认后创建，携带安全的会话摘要和已确认事实。

8. Eval方案

规模：400条 = 120核心Gold + 280结构化变体；同时按用途拆280回归 + 120封闭验收，语言拆280印尼语 + 120英语。

每条至少验证：问题理解、处理方式、数据、知识/版本、最终回答、安全、工单。错误分类：Intent/Route/Retrieval/Knowledge/Data/Generation/Safety/UX。

训练发布阈值：回答准确≥90%、分类≥95%、处理方式≥95%、检索≥95%、版本=100%、会员数据忠实=100%、高风险=100%；旧规则、跨会员、支付事实伪造、资产写入等零容忍。以上为课程项目训练门槛，不冒充真实上线指标。

9. Mini PRD与QA

PRD至少包含：问题/目标、范围/非目标、用户流程、状态、处理策略、知识、数据、权限、安全、人工、埋点、Eval、QA和发布标准。QA与AI Eval分开：QA验产品功能/E2E，Eval验AI链路决策与答案质量。

10. 灰度与线上

训练灰度节奏：内部→5%→20%→50%→100%。每一级同时看高风险错误、解决/人工介入、失败率、时延和新问题分布。任何跨会员、支付事实伪造或资产写入应停止放量并定位最早错误层。

11. 项目复盘表达

2分钟主线：业务问题 → 为什么AI适合 → 一期范围/红线 → 核心方案（规则+本人数据+人工）→ 怎么用Eval和灰度保证质量 → 最大反思（AI项目的难点是业务事实、权限、知识版本和评测，而不只是模型）。
